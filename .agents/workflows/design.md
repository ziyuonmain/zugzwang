---
description: Design a small project feature before implementing it
---

Before proposing a design:

- Apply relevant workspace skills automatically.
- Read applicable project rules.
- Reuse accepted ADRs and existing architecture.
- Do not reopen previously accepted decisions unless new evidence creates
  a concrete conflict.

For the requested feature:

1. Read the project rules.
2. Inspect relevant repository files.
3. If railway data semantics matter, use the rail-data-research skill.
4. State the user problem in one paragraph.
5. Identify relevant constraints.
6. Propose the smallest viable design.
7. List files/resources that would change.
8. Identify risks and unknowns.
9. Explicitly list what should NOT be built yet.

Do not implement anything.

Return the proposal for human review.
